# 1.5.19：首次采集时的历史日志 source map

1.5.18 在绑定日志与脚本身份时引入了初始化回归：首次调用
`enable_console_collection(source_maps=True)` 会先开启 Runtime，Chrome 立即回放
已有日志；此时 Debugger 尚未建立脚本目录，日志会把缺失的脚本描述固定为 `None`，
之后无法映射回原始源码。

修复将首次初始化调整为先开启 Debugger、接收脚本元数据并配置异步堆栈，再注册
控制台回调并开启 Runtime 接收回放。脚本身份绑定规则保持严格，旧日志仍不会查询
新站点的脚本描述。初始化失败时关闭本次管理的 Debugger 采集并移除回调，保留原始
错误和外部回调，支持重试。普通控制台采集仍只开启 Runtime。
Runtime 回放执行上下文时，也会补齐当前存活脚本的唯一上下文身份，确保同一页面
关闭再开启 source map 时，未缓存的映射仍可加载；已销毁上下文的脚本不会被补写。

新增真实 Chrome 用例先加载带 source map 的页面、让其输出日志，再开启采集，验证
日志详情和列表均显示原始 `.ts` 位置；随后跨站导航并复用 script ID，验证旧日志与新
日志分别使用正确源码。该用例在原始 `1f0aecd` 上失败，修复后通过。
另有两个单元测试覆盖回放时的绑定以及初始化失败后的清理、原始错误透传和重试。
执行上下文单元测试和上述 Chrome 用例还覆盖关闭/开启后的未缓存映射与上下文 ID
复用，确保补齐身份时不会把旧脚本归到新的执行环境。
